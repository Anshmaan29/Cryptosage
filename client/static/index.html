    Why this project exists
    Compare equivalent level-3 post-quantum KEMs while making security policy, identity trust and actual performance visible. Algorithm choice is automatic; mandatory security restrictions always win.
    One trust boundary, three processes
    Alice’s local Python client encrypts a message, the untrusted relay forwards its opaque envelope, and Bob’s independent local client authenticates and decrypts it. Each browser talks only to its own loopback client.
    Two KEMs, different maturity
    ML-KEM-768 is standardized in FIPS 203. HQC-3 is the current liboqs level-3 identifier, selected for future standardization and experimental in this prototype. ML-DSA-65 authenticates the negotiation; fingerprint pins establish which identity is trusted.
    What the ratchet guarantees
    Directional HKDF chains derive fresh message keys, and authenticated fresh sessions renew key material. This simplified research protocol is not Signal’s full Double Ratchet.
    Recorded experimental findings
    Run a benchmark to show actual findings from this environment.
    Limits of the evidence
    Tests exercise real implementations but do not prove protocol security. This remains an independently unreviewed university prototype. Cloud measurements do not establish MacBook, LAN or WAN performance.
    Python cannot guarantee complete secret erasure. Local storage protection and its limits are documented; the relay never stores endpoint secrets.
